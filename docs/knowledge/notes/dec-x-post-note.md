起案者の指示（2026-10-21「Xと連携して、ツイートを感想として紐付けられると便利そう」）。

- **案は 3 つ出した:** A. 感想の欄にポストの URL を貼る。B. X でログインして自分のポストを拾う。C. X のアーカイブ（zip）から選ぶ。
  起案者は「togetterみたいにログインしたら自分のツイート一覧から対象のツイートを選べるとよい」と答えた。一覧を出すには X の API でポストを読む必要がある。X の API は 2026-02 に無料枠をやめて、読む 1 件ごとの課金（0.005 ドル）になった（第三者のまとめ。X の Developer Console が正）。100 件の一覧を開くたびに約 75 円かかり、無料の約束（dec-free-tier-only）に反するので見送った。代わりに C を出したところ、起案者は「最初に提示してくれた、リンク貼る方式にしましょう」で A に決めた
- **読み方:** X の埋め込み用の口（publish.twitter.com/oembed）は、公式の文書では鍵が要らず、回数の上限も無い。Worker が貼られたポスト 1 件の本文と日付だけを読む（/api/x_post）。鍵のかかったポスト・消されたポストは読めないと伝え、URL をそのまま入れる。誰のポストかは確かめない。記録は本人にしか見えないので、他の人のポストを貼っても害は無いと判断した
- **残し方:** 本文は感想の文としてコピーする。ポストが後で消えても感想は残り、感想の好み（#104）にもそのまま効く。最後の行に「[X 日付] URL」を残し、画面ではその行を外して「2026/10/08 の X のポストから · X で見る ↗」と小さく出す（起案者の選択「本文＋『X で見る』リンク」）。X の埋め込み（widgets.js）は使わない。外のスクリプトを読み込むことになり、見たことが X に伝わるため。表に列は足さない。感想の文 1 つに入れれば、書き出し・控え・移行の形を変えずに済む
- **書き直し:** その場で書き直すとき（editInPlace）も、出どころの行は data-xsrc に持っておき、保存のときに文の後ろへ付け直す。文を全部消したら出どころも外す
- **感想の好み:** 出どころの行（URL）は読まない（impression.js・impression_preferences.py の両方）
- **確かめていないこと:** 手元からは X に出られない（作業環境の外向きの通信の制限）ので、本物の oEmbed の答えは公式の文書の形で試験を書いた。本番で最初に貼ったときに読めることを確かめる
