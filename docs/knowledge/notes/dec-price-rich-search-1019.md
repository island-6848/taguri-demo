起案者の指示（2026-10-19）:
「価格帯の表示を修正して。折りたたむ前は『min円～max円』（min=maxならばmax円）。展開したら『S席 max円 / A席 min円』・・・などの表示。あと座席に『指定』とか『自由』が書いてあるならそれも必ず明記してほしい」
「あらすじ、凝ってるものはそのまま入力できるようにしたい（中央寄せとか、書体変更のやつたまにある）管理者画面でその辺の書体管理したまま入力できる欄に変えて」
「検索結果、新しい順から15件表示するのではなく、ちゃんと全件表示して」

決めたこと:
- 価格帯（app.js priceSummary）: 閉じた 1 行は明細の金額のいちばん安い〜いちばん高い（同じなら 1 つ）。料金の欄に座席の決まり（全席指定・全席自由・指定席・自由席・日時指定・整理番号付自由・立見）があれば閉じた行の頭に置く（「全席指定 6,000円〜12,000円」。起案者の指示 2026-10-19「全席指定（または自由席） 〇円〜〇円のほうがいいな」）。開くと券種ごとの行を高い順。座席の決まりが券種の名前に無ければ「S席(指定)」と添える。券種が 1 つで閉じた行と同じなら開く中身は無い。会場ごとに料金が違うカード（日程の表に料金がある）はこれまでどおり。
- 書式つきのあらすじ: 管理画面の欄を書式の効く入力欄（contenteditable）にし、太字・斜体・下線・左/中央/右寄せ・小さく/大きく・明朝/ゴシック・書式を消す、の押し口を付けた。書式ごと貼り付けたものも、許した形に直して入れる。入れられる書式を決まった形だけに絞るため（貼り付けた色・背景・位置などを持ち込まない）、寄せ・大きさ・書体は決まった class（ta-left/center/right・fs-s/l・ff-mincho/gothic）で持ち、頭に <!--rich--> を付けて stage_override.synopsis に置く。本番の Worker（override.richHtml）が許した札（p br div span b strong i em u s small）と class だけに絞り直して出す（script・style 属性・リンク・画像は落ちる）。カードでは書式を保ったまま高さで畳み、はみ出すときだけ「続きを読む」。題材の読み取り（Claude Code）・検索などには文字だけを渡す（admin.plain_synopsis・override.richText）。書式の無い入力は、これまでどおり文だけで保存する。
- 探すの結果: 見つかった分を全部たどれるようにページ送りを付けた（起案者の指示 2026-10-19「ちゃんと全件表示して。サーバーで問題があるならページ送りをつけて」）。過去の公演・これから観られる公演とも 1 ページ 5 件（同じ日の後の指示「5 件ずつ表示し、ページ送りで最後までたどるように変えて」。前は過去の公演が新しい順に 15 件まで、これから観られる公演が上演日の近い 8 件まで）。ページを移っても言葉・月・カレンダーの側はそのまま。題名で引く過去の公演の行は 1 回の検索で 1,000 行まで（短い言葉で何千行も読まないため。D1 の読み取りの無料枠）。越えたときはそう書く。

確かめたこと: 単体の試験（JS・Python）。e2e の段「探すのカード: 価格帯の幅と券種・書式つきのあらすじ」（閉じた行「6,000円～12,000円」、開いて S席 12,000円 / A席 8,000円 / U-25 6,000円、中央寄せと明朝が効き script が残らない）と、電話の幅の写し。管理画面の欄は Chromium で、貼り付けた書式（style の text-align・font-family・font の size・h2）が決まった class に置き換わることを確かめた。管理画面を本物の D1 につないだ保存までは試していない。

- 観劇記録の追加で「これを使う」で選んだ公演は、上演期間を観た日の欄の選べる範囲（min・max）にする。日付の欄のカレンダーは、空のときは今日を範囲に寄せた年月で開くので、その公演の年月から開く（同じ日の指示「選んだ公演があるなら、観た日のカレンダーの表示を最初からその年月にして表示してほしい」）。候補（/api/suggest）に上演期間（start・end）を足した。題名を打ち直す・登録すると範囲を外す。カレンダーが開く年月は Chromium の仕様（空の欄は今日を範囲に寄せる）によるもので、ほかのブラウザ（iPhone の Safari など）での開き方は確かめていない。
- 選んだ公演の開演時刻が分かる日は、開演時刻の欄をその時刻だけのプルダウンにする（同じ日の指示「観た日の時間、も最初からわかってるならその時間しか選べないようにプルダウン化してよい」）。GET /api/stage_times（suggest.stageTimes）が、公演のタイムテーブルの欄（管理者が直した分も重ねる）を schedule.parseTimetable で読み、日ごとの時刻を返す。貸切の回と、時刻の無い回（マチネなど）は入れない。分からない日・公演は、これまでどおり自由に入れる欄。D1 の読み取りは公演を選ぶたびに数行。画面でプルダウンに切り替わる様子は、観劇記録の追加の画面の e2e が作り替え（#219〜）で通らないため、まだ見ていない。
