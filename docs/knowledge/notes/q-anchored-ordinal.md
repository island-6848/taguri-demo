起案者（2026-10-20）「プレゼン資料のアルゴリズムの図2のように、◎が多かったからって◯のzがマイナスになるのはまずい。せめて◎◯は常に+で受け取らないと。それは星でもそうで、星4〜5は少なくとも+だと思う。微妙なのって△とか3〜3.7あたりかな。」指示は「検討→修正。いきなり実装しない」。

今の式（式 1–2）は z の平均が必ず 0 になるので、甘めの人では ○・★4 が負になる（図 2 の B: ○ −0.866。★3/4/5 を 1/4/5 件付けた人の ★4 は −0.693）。全部 ◎ の人は z がすべて 0 で推薦が出ない〔q-all-same-ratings-no-reco〕。

検討した案（数は手で計算した例。当たりへの効き目は未確認）:
- 案 1（両側で別に数える）: 尺度ごとに「真ん中の段」を決め、その段は z ＝ 0。上の段は、上側の評価の中での位置で 0〜+√3、下の段は下側の中で −√3〜0。めったに付けない ◎ ほど強い性質は残る。A: ×−0.866・△0・○+0.495・◎+1.361。B: △0・○+0.289・◎+1.155。全部 ◎: +0.866（推薦が出る）。◎9・○1: ○+0.087
- 案 2（錨までずらすだけ）: z ＝ √12·(F − F(真ん中))。A: ×−0.52・○+1.039・◎+2.252。B: ○+0.693・◎+2.252。下側の評価が弱くなり、最大値が人によって大きく振れる
- どちらも z の平均は 0 でなくなる（甘めの人ほど正の人物が増える）。お気に入りの仮の評価 z0（式 9）、裏の答え合わせ（3.11）の釣り合いを見直す必要がある

真ん中の段の案（起案者の言葉から）: ○△× と ◎○△× は △、星 5 段階は ★3、0.5 きざみは ★3〜★3.5、○× は真ん中なし（境目）。

確かめ方: 前に採用を決めた公開の映画評価（Douban、500 人、eval_person_reco.py）で、今の式と案 1・案 2 を同じ手順で比べる。データはリポジトリに無いので取り直す。Python と Worker を同じに直し、推薦の控えの版を上げる。
