起案者が案 1 を「それでいいので進めて」と言ったので（2026-10-20）、前に今の z を採用したときと同じ手順（eval_design_choices の手順。Douban 映画、500 人、評価の 40 件を答え合わせに取り、前の k 件だけを見る。auc_top と pairs の平均）で比べた。違うのは評価を数にする所だけ（真ん中は ★3）。スクリプトはリポジトリにあり、データは入れていない。

結果（seed 1 → seed 2、今の z との差。95% 区間は ±0.004〜0.005）:
- 案 1（両側で別に数える）: k=10 −0.004 → −0.001、k=40 −0.029 → −0.029、k=80 −0.042 → −0.045。良くなった人は k=80 で 20%。甘めの人（平均 4 以上、155 人）でも −0.050
- 案 2（錨までずらす）: k=80 −0.051 → −0.054。さらに悪い
- 案 3（今の z のまま、★4〜5 は 0 未満にしない・★1〜2 は 0 より上にしない）: k=80 −0.0017 → −0.0014（±0.0012）、甘めの人は −0.005 → −0.005（±0.004）。小さいが、2 回とも同じ向きに下がる

読み: 「◎ が多い人の ○ は、その人にとってはいつもより下」という情報が当たりに効いている。案 1・2 は ◎ と ○ の差を縮め、何本も観た人ほど値が積み上がる形になる。どちらも、本人の評価どうしの順位を当てる物差しでは不利になる。

分からないこと: この物差しは「本人が観た作品どうしの順位」なので、「○ の人をおすすめの理由で下げる」ことが本人にどう見えるか（納得感）は測っていない。舞台のデータでは測っていない。全部 ◎ の人に推薦が出ない問題は案 3 では直らない（q-all-same-ratings-no-reco の案 1 が別に要る）。
