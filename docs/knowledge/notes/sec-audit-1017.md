起案者の指示（2026-10-17）「今セキュリティ上の問題ないか全て調べて。個人のデータの保存先とか、ログイン情報が漏れないかとか」。
4 つに分けて読み取りだけで調べ、出てきた指摘はコードで確かめてから直した。

## 問題が無かったところ（主なもの）
- **セッション：**
  - トークンは 32 バイトの乱数で、データベースには SHA-256 のハッシュだけを置く。
  - Cookie は HttpOnly・Secure・SameSite=Lax。
  - POST はすべて Origin を確かめる。
- **Firebase の ID トークン：** RS256 の署名と、aud・iss・exp・auth_time を確かめている。
- **パスキー：** 本人確認（生体認証・PIN）が必須。チャレンジは一回限り。
- **復旧コード：** 256 ビットの乱数。
- **ほかの人の記録に触れないか：** すべての SQL が `ctx.uid` で絞られている。ほかの人の行を読み書きできる経路（IDOR）も、SQL インジェクションも無い。ログインせずに使える書き込みも無い。
- **外への通信（SSRF）：** つなぎ先は固定（カレンダーの ics・smtp.gmail.com）。
- **/img/：** `/` を通さないので、R2 の控え（backup/d1/）は読めない。
- **XSS：** 画面の文字列はすべて `E()` を通す。カードは `html.escape` を通す。公式サイトのリンクは http(s) だけ。
- **ログ：** 秘密の値・利用者の記録は出さない。リポジトリにも秘密は入っていない。Firebase の Web API キーは公開前提のもの。
- **アカウント削除：** user_id を持つ表はすべて消す。fix_request は、0030 のトリガーで送った人と本文を消す。

## 直したもの
1. **（中）人の流れの図の保存型 XSS。** 図のデータを `<script type="application/json">` に入れるとき、`<` を逃がしていなかった。クロールした題名や人名に `</script>` があると、そこで閉じてスクリプトが動く。JS 版と Python 版の両方で `<` にした。
2. **（中）1 つの接続元から新規登録の枠を使い切れた。** 新規登録を、接続元ごとに 1 日 3 件までにした（`usage` に IP と日付のハッシュを、その日のうちだけ置く）。プライバシーの説明も合わせた。
3. **（中）復号した控え（平文の SQL）がコミットされ得た。** `.gitignore` に `*.sql`・`*.sql.gpg` を足した（migrations は除く）。戻しの手順書では、復号先を `mktemp -d` にした。
4. **（中）控えの書き出しが失敗すると、平文が取得の state ブランチに残り得た。** `backup_d1.py` は書き出しも予行も一時ディレクトリで行い、必ず消す。`crawler_state.keep` も `.sql`・`.sql.gpg` を入れない。
5. **（低）wrangler のエラーの写しに SQL の文が混ざり得た。** SQL らしい行を落としてから例外にする。
6. **（低）復旧コード・新規登録で、その端末の古いセッションが残った。** ほかの経路と同じく消す。
7. **（低）パスキーの削除に、ログインし直しが要らなかった。** 盗んだ Cookie だけで締め出せないよう、10 分以内のログインを求める。
8. **（情報）その他。** ログアウトの Cookie の読み方を `sessionCookie()` にそろえた。削除画面の控えの説明に「毎日の控えに 30 日」を足した。

## 起案者に決めてもらうもの
- **公開リポジトリに、持ち主の実際の購入記録が入っている。** `tools/taguri/demo_purchase_works.json` の 96 件で、これからの観劇の日時と劇場もある。コミットの作者のメールと合わせると、本人の居場所が分かる。今の版から消すか、日付をずらすか、さらに履歴から消すか（force push が要る）。
- **第三者の実在のメールアドレスが入っている。** `tools/mail/send_daily_report.py` の宛先が直接書いてある。設定ファイルへ移すか。

## あとで直すもの
- **CSP：** `'unsafe-inline' 'unsafe-eval'` を外すには、インラインのハンドラを委譲に移す必要がある（q-original-ui-csp）。
- **ヘッダー：** 本番で `/rate`・`/terms` の応答に CSP などが付いているかを確かめる。独自ドメインに移すときは HSTS を足す。
- ~~**パスキーの未処理チャレンジの上限（1000）が全員共通。** 多くの接続元から埋められる。~~ 2026-10-18 に直した（issue #73）。接続元ごとに 10 件までにした（migration 0032 の addr。日と住所のハッシュで、住所そのものは持たない）。全体の 1000 件を埋めるには、100 か所が要る。
- ~~**過去の公演の検索の 1 日 150 回が全員共通。** 1 人で使い切れる。~~ 2026-10-18 に直した（issue #73）。1 人 1 日 20 回までにした（usage に日と利用者のハッシュで数える）。
- **控えとポスターが同じ R2 バケットにある。** 分けるのが安全。
- **空のまま使われないアカウントを消す仕組みが無い。**
