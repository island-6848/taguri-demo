#138 の続き。細かい直しで 2〜4 倍速くしたが、評価 50 件で約 24 ms、300 件で約 110 ms（Xeon 2.1 GHz の計測）。案:
1. **点数付けを D1 の SQL に移す**: 利用者の人ごとの値を表に書いておき（評価を書くたびに更新）、rec_credit と結んで公演ごとの上位 3 人・下位 3 人・種類の平均を SQL（窓関数）で出す。D1 で待つ時間は CPU に数えない。代わりに D1 の読み取り行（無料 1 日 500 万行）を使う。Python の参照実装と round6 の一致をどう保つかが難しい
2. **点数を付ける人数に上限**（|値| の大きい順に 400〜600 人）: いちばん簡単。小さい値の人は上位 3 人にほとんど入らないので順位はほぼ変わらない見込みだが、測ってから。試験の作り物の利用者は上限より少ないので Python との一致は保てる
3. **書くときに計算**: 評価・興味ありを書く要求で人ごとの値を更新して保存し、画面の要求では値を読むだけにする
4. **計算を 2 回の要求に分ける**: 1 回目で点数、2 回目で束ね・会場（それぞれ 10 ms 以内）
どれも順位や D1 の使い方が変わるので、起案者に選んでもらう。おすすめは 2（すぐ・小さい）を入れ、1 を調べる。
