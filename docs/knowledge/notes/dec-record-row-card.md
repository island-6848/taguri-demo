起案者の指示（2026-10-13）「評価一覧の画面も同じデザインにそろえて」「書き直す押したら下にテキストボックス出すのではなく、そのうえに書いてある斜体の文章直接編集できるようにして」。
見た目（web/theme.css の .rec-row まわり）:
- 前は罫を敷いた帳面（左の余白に明朝の日付と判子、右にテープで貼った傾いた半券、感想は明朝の斜体）。1 件 1 枚の白い紙にし、切り取り線（点線）の左にポスター、右に 日付（月日・曜日・年を 1 行）・題名・どこで観たか・判子、その下に全幅で あらすじ・出演と作り手・押し口・感想・公演詳細を直す
- HTML は Render の Python（app.py の _rec_row）のまま。.marg と .page を display:contents にして中身を 1 枚の格子に並べ直した（Render を起こし直さずにデモ版・サービス版の両方へ届く）
- あらすじ・出演・作り手・感想の見出しを左の列（4em）にそろえた（おすすめの「出演」「あらすじ」と同じ）。感想は斜体・明朝をやめ、本文と同じ字
- 年の見出しはえんじの耳をやめ、小さな見出しに細い線
- 判子（◎○△×）はそのまま（「評価はハンコのまま」）
- 同じ行を使う 日記帳・感想・未評価などの画面も同じ形になる
書き直し（web/app.js の editInPlace）:
- 書いてある感想・この回のメモの「書き直す」を押すと、その文がそのまま書ける欄になる（contenteditable="plaintext-only"）。押し口は「書き終える」に変わる。離れるか「書き終える」で、今までと同じ口（/api/note・/api/visit_note）に保存し、文の下に「感想を保存しました」。Esc で元に戻す。保存できなかったら元の文に戻す
- まだ何も書いていないときの「感想を書く」は今までどおり入力欄を開く
別画面向けの規則が効いていたので打ち消したもの: `.wd{width:150px}`（曜日が別の行に落ちる）、`.rb`・`.inr .wnb` の `margin-left:auto`（右に寄る）。
確かめたこと: Python の _rec_row で作った 2 件と、見た目の検査の日記帳の見本を 390px・1280px で描いた。書き直して「書き終える」を押すと /api/note に書き直した文が送られ、文の下に「感想を保存しました」が出る。見た目の一致の検査（12 画面、差 0）とデモの画面テストが通った。

追記（2026-10-13・2）: 起案者の指示「今のデザインに合わせて」（日記帳などの「作品でまとめる」「2026 年」の切り替え）。えんじの縁取りと塗りの「索引の耳」（.idx .ix）をやめ、行き先の帯と同じ形にした ── 白い札に細い灰の線、開いているものだけ薄いえんじで塗る。耳が挟まっていた帳面（.idxsheet）の上端のえんじの線と白い地も外し、状態の 1 行（.mnow）は小さな灰の文にした。
