起案者「カードがない新しい公演も検索で出るようにして」「検索、もしワードが入って検索されてるなら、次のところも該当件数のみ表示されるようにして」（2026-10-17、「ふぉ〜ゆ〜」で探して 0 件の画面の写真つき）。
- 0 件だった理由は 3 つ（作業データ state ブランチの candidates.jsonl で確かめた。本番の D1 は読めない）
  1. 取得元の書き方は「ふぉ～ゆ～」（U+FF5E）、打った語は「ふぉ〜ゆ〜」（U+301C）。NFKC は FF5E を ~ にするが 301C は変えないので、一致しない。→ 〜 ～ ∼ ⁓ ˜ を ~ にそろえて比べる（SQL 側も replace でそろえる）
  2. ふぉ～ゆ～は出演欄で「越岡裕貴（ふぉ～ゆ～）」と名前の後ろの括弧にだけ出る。名前の読み取り（credits.parseCredits）は括弧を外すので、人の名前としては当たらない。→ 題名・団体で当たらないときは、欄の文そのもの（、で区切った 1 つ）でも当てる
  3. 探すはカード（rec_card）のある公演しか見ていなかった。カードは書き込み予算に収まる日にしか入れ替わらないので、新しい公演が出ない
- 直したこと: これから観られる公演＝索引（rec_stage）の終わっていない公演＋索引にまだ無い一覧（catalogue）の公演。カードの無い公演は fallback.fallbackTemplate で描く（その場で興味ありを押せる）。おすすめ画面の「おすすめに出てこない公演を探す」〔impl-recommend-find〕も同じ関数なので同じく広がる
- 言葉が入っているときは、下の「観た記録」「これから観られる公演」の札の数とカレンダーの月の数を、当たったものだけにする（「『…』に当たったものだけを数えています」と書く）
- D1 の読み取り: 一覧は終わった行も残るので、初日が 366 日以内の行だけを日付の索引（catalogue_date）で読む。言葉なしの月の数は日付の列だけを読む（入り口の JSON を読まない）
