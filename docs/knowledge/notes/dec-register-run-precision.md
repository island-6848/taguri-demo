起案者の指示：「見た日じゃなくて、上映日程で絞り込める形にして、上映日程は月、月日、年月日など細かさを任意で選べるようにして。」演劇の画面なので表示は「上演日程」にする。

- 詳細検索の上演日程は、指定なし・月・月日・年・年月・年月日から選ぶ。選んだ細かさに必要な欄だけを表示し必須にする。無関係な欄は検索APIに送らない。
- 「10月」は年を問わず10月に上演期間が重なる公演、「10月19日」はいずれかの年のその日を期間に含む公演、「2026年10月」はその年月に重なる公演、「2026年10月19日」はその日を含む公演。初日と千秋楽を含む。
- 月・月日は年をまたぐ期間も扱う。2月29日はうるう年の実在する日だけに一致させる。不正な月日や不完全な指定はエラーにする。上演日程を指定したとき、期間不明の公演は一致させない。
- 日程検索の値を「観た日」にコピーしない。観劇日の入力とは独立した条件にする。前のアプリをキャッシュした端末のため、旧APIの完全な日付パラメータだけは受け付ける。
- 題名索引と手動検索の上限は維持する。過去公演は最大200候補に条件を適用して20件まで採用。現在の索引も手動の詳細検索では最大200候補に条件を適用する（自動候補は従来どおり20件）。年なしの日程は1候補あたり最大9年分の照合に抑える。閏年を飛ばす世紀境界の8年間隔も含む。外部取得・定期実行・保存項目は増やさない。
- 詳細検索ダイアログ・同じ作品の連続追加・同じ日時の重複拒否は前の決定から維持する。

検証：期間の重なり、年越し、月末、年指定の有無、うるう年と2100年付近、無効な指定、20番目より後の候補（現在と過去）、必要な日程条件だけの送信、観劇日へ転記しないことを含むテスト10件が通過。ブラウザの表示とキーボード操作の実機確認は環境制限のため未完了。
