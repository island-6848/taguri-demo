起案者の指示（2026-10-13）「ポスターが大事なのに、スマホ版はポスターの場所がないので足して。『今週のおすすめ』は縦スクロールになりすぎないようにしたいので、各公演に載せる情報のレイアウトを見直して」。
デザイン案（Main の画板）に当てた形:
- 半券の切り取り線の左側（もぎり）をポスターにする（72×102、2:3 に近い縦長）。左上に順位。ポスターの無い公演は、灰の地に公演名と「ポスターなし」
- 右側は 初日・発売の状態／公演名（2 行まで）／劇団・劇場（1 行）／たぐった糸の 1 本目（残りは「ほか n 本」）だけ
- その下に回答の帯（興味あり・興味なし・持っている、全幅で 1 行）と「くわしく」の開閉ボタン
- 会期・料金・出演・あらすじ・たぐった糸の全部・なぜ気になったか・公式サイトは「くわしく」を押すとすだれで開く
1 件の高さは閉じた状態で約 190px（前の案は 1 件 450〜520px）。390px の画面で 3 件強が一度に見える。
「すでに持っている」は 1 行に収めるため「持っている」に縮めた（実サイトの文言を変えるかは承認待ち）。

追記（2026-10-13）: 起案者の指示「各公演を折りたたむとき、出演者順に５人とあらすじ（最初の１文くらい）が表示されるようにして。おすすめ理由は全部表示（ただしおすすめ理由が多すぎるときは折りたためるように）」「そのデザインを本番環境（サービス、デモ）にも反映させて」。
閉じた 1 枚: ポスター（順位をその左上）／日付・公演名・団体と劇場・発売／全幅で 出演 5 人（出演順、残りは「ほか n 名」）・あらすじの最初の 1 文（句点まで、長ければ 90 字で切る）・おすすめ理由の全部（4 本目からは「ほか n 本の理由を見る」で畳む）・回答の帯・「くわしく」。
「くわしく」の中: 会期と料金・ツアーの日程・出演と作り手の全員・あらすじの全文（手で入れる口も）・公式サイト。
本番への入れ方: 画面の HTML は Render の Python（render_recommend.py の ticket）が組むが、Render は起こし直すと止まるおそれがある〔q-render-s3-dependency〕。そこで HTML は変えず、画面側の web/app.js の compactTickets() が受け取った 1 枚を組み替え、web/theme.css で形を付けた。web/ は GitHub Pages（デモ版）に、cloudflare/public の写しは Workers（サービス版）に master から出る。推薦と「興味あり」の 1 枚に効く（お気に入り・購入済みは今のまま）。
確かめたこと: 実際の ticket() で作った 3 枚を、390px と 1280px で Chromium に描いて見た。390px で回答の帯は 1 行（高さ 40px）、閉じた 1 枚の高さは 500〜550px（理由 1〜3 本）。cloudflare の node テスト 54 件、見た目の一致の検査（web と cloudflare/public）、runtime-smoke、デモの画面テストが通った。
分からないこと: 実データ（ポスターの縦横比・理由の本数）での見え方は本番で見るまで分からない。Render の返す HTML そのものは描いて確かめていない（ここから Render へは繋がらない）。

追記（2026-10-13・2）: 起案者の指示「くわしく、を押したとき『ほか6名』が展開されて、今くわしくで出る名前たちが出るようにしてほしい」「あらすじは最低1文目までは折りたたんでる状態でも表示」。
- 出演: 閉じた行に 6 人目以降を隠して持たせ、「くわしく」を開くとその行のまま全員を出す（「ほか n 名」は消える）。「くわしく」の中の出演の行は重ねて出さない（演出・脚本などの作り手の行と出典は残す）
- あらすじ: 最初の 1 文は閉じていても必ず出す。起案者のスマホの画面で 1 文目が出ていない公演があった。Render の今のサーバーの HTML が本文を `.txt` で包んでいない古い形の可能性があるため、`.txt` が無いときは出典・タグ・押し口・入れ口を除いた残りから拾うようにした。あらすじそのものが無い公演（`.syn.no`・`.syn.part`）は出さない
分からないこと: 起案者の画面で 1 文目が出なかった本当の原因（その公演にあらすじが無いのか、HTML の形が違うのか）は、ここから Render の HTML を見られないので確かめていない。

追記（2026-10-13・3）: 起案者の指摘「どこからがあらすじの1文目なのかわかりにくい」。閉じた 1 枚の出演の行とあらすじの 1 文が続けて並び、見出しが「出演」にしか無かった。あらすじの 1 文にも「あらすじ」の見出しを付け、2 つの見出しを左の列（4em）にそろえて、折り返した行は本文の頭にそろえた（見出しは小さな灰）。

追記（2026-10-13・4）: 起案者の指示「見出しの下のえんじの縞の帯も消して。スマホ版で公式サイトへのリンクは発売済みの丸の右に」。
- 縞の帯は style.css の `.curtain`（前の「舞台の意匠」の幕）。theme.css で `display:none` にした（全画面）
- 公式サイト: 640px 以下では、compactTickets が「発売済み」などの丸と同じ行に小さな押し口（高さ 32px・枠付き）を足し、「くわしく」の中のボタンは隠す。パソコンでは「くわしく」の中のボタンのまま
残っている前の意匠: パンくずの後ろの黄色い光（style.css の `.spot::before`）。まだ消していない。

追記（2026-10-13・5）: 起案者の指摘「ぼんやりした光消して」「ボタン押したら文字のせいで長くなるのどうにかして。興味ありだけ黒いのなぜ？押したら色変わるとかなにかしらのアニメーション」。
- パンくずの後ろの黄色い光（style.css の `.spot::before`）を theme.css で出さないようにした
- 「記録しました。入れ替わりに…」（`.said`）が回答の帯の右に詰められて 1〜2 字ずつ折り返し、縦に長く伸びていた。半券の中の回答の帯を grid（押し口 3 つ＋残り）にし、`.said` は帯の下の行に全幅で出す。押し口は折り返さない
- 回答の 3 つを同じ白い押し口にした（前は「興味あり」だけ最初から濃く塗っていた ── いちばん押してほしいものを目立たせる意図だったが、押したあとと区別が付かなかった）。押した 1 つに `.picked` を付け、興味ありはえんじ・ほかは濃い灰に塗り、✓ を添えて縮んで弾む動き（0.38 秒）を出す。ほかの 2 つは薄くなる。記録できなかったら印を外す。動きを減らす設定では弾まない
確かめたこと: 390px で「興味あり」を押したあと、帯は 1 行のまま、案内の文は帯の下に 2 行で出る。見た目の一致の検査（12 画面、差 0）とデモの画面テスト、cloudflare の 54 件が通った。

追記（2026-10-13・6）: 起案者の指示「パソコン版のおすすめ画面も同じ形にそろえて」。
- 公式サイトの小さな押し口（「発売済み」などの丸の右）を、スマホだけでなくパソコンでも出す。「くわしく」の中のボタンはどの幅でも隠し、「くわしく」の見出しの説明から「公式サイト」を外した
- パソコンで回答の帯が右へ 34px ずれ、上の線が 3 分の 1 の長さで切れていた。style.css の別画面向けの `.act{width:33%;min-width:210px}` と `.btns{margin-left:auto}` が半券の中にも効いていたため。半券の中では幅を外し、左寄せにし、上の線（「くわしく」の線と重なる）を外した
確かめたこと: 1280px で 1 枚目を描いて、スマホと同じ並び（ポスター／日付・公演名・劇団と劇場・発売の丸と公式サイト／出演・あらすじ／理由／回答の帯／くわしく）になっていることを見た。見た目の一致の検査（12 画面、差 0）も通った。

追記（2026-10-13・7）: 起案者の指示「やっぱ公式サイトのボタンはポスターの下に」。発売の丸の右に置いていた小さな押し口を、ポスターの真下（ポスターと同じ幅・11px の字）に移した。スマホもパソコンも同じ。ポスターの無い公演は「ポスターなし」の枠の下に出る。390px と 1280px で描いて確かめた。

追記（2026-10-13・8）: 起案者の指摘「タイトル、主催団体、会場の文字サイズが同じでわかりにくい。タイトルはちょっと文字サイズ大きくしたほうがいい。主催団体と会場は改行して表示（ツアー公演で複数会場ある場合も考えて）」。
- 公演名を 18px（パソコン 19px）の太字・本文と同じ字にした（前は明朝で主催・会場と同じ大きさに見えた）
- compactTickets が `.meta`（団体／劇場（都道府県））を 2 行に組み直す: 1 行目が主催（団体）、2 行目が会場（灰）。ツアーの日程（`.tourfull .tf-row`）が 2 行以上あれば会場の行に「ほか n 会場」を添える（会場の一覧は「くわしく」の中のまま）
確かめたこと: 見本の 1 枚にツアーの 3 会場を足して 390px で描き、「下北沢 本多劇場（東京都）ほか 2 会場」と出ることを見た。
