## 今回の実装

元のHTML・CSS・JavaScript・ナビゲーションを使い、元Pythonの17画面生成関数と一般利用者の操作処理を再利用する。新しいデザインへ置き換えない。

軽いWorkers入口からSQLite-backed Python Durable Objectへ処理を渡し、永続保存はD1へ集約する。通常Workerの無料CPU制限内へ重い元画面処理を無理に押し込まず、無料対応DOの既定CPU枠を使う。有料プラン変更や有料CPU設定は追加しない。

- 要求ごとに本人のD1記録だけを一時SQLiteへ復元し、元の同期処理を実行する。処理中はawaitせず、モジュールのDB参照・キャッシュをfinallyで戻す。
- 全user_idテーブルの全列を保持する。主キーに基づく変更行だけをD1の単一batchで保存し、revisionの比較で同時更新の上書きを防ぐ。
- 元の作品単位の評価・感想と、回別visit_noteを区別する。観劇回、動機、反応理由、券、除外・統合、手動情報等を部分変換だけで済ませない。
- 既存D1簡易版のコード・セッションを維持し、元形式へ一度だけ変換する。全元列をnative_sourceに保存し、原表を削除しない。
- 復旧、期限付き一回限りの6桁端末追加、登録・復旧の試行制限、ログアウト、本人だけの出力・削除を接続する。
- 旧復旧コードは秘密pepperと移行済み利用者対応表が揃った場合にだけ元のscrypt方式で確認する。旧Cookieも、保護された移行済みセッションだけを認める。
- 公開カタログ・クレジット・ツアーの日程や会場・料金・販売情報を明示した構造で保持し、私的な感想・メール・認証情報を同梱しない。
- 操作ログは固定イベント・許可された操作名・method・status・所要時間等に限定し、生Cookie、復旧コード、メール本文、感想、URLクエリ、例外内容を記録しない。

実装と操作手順: [Python移行版README](../../cloudflare/python/README.md)、[認証接続契約](../../cloudflare/python/AUTH-CONTRACT.md)。

## 公開版との違い

公開中の移行版はコミット `b889151d614ce65320bab15db663ce95e6e94e59` を基準とし、元UIの保存・処理にRenderを使っている。今回のPython移行版は別名・別DBの検証設定で、`MIGRATION_READY=false`。存在しない本番データを勝手に作ったり、旧アカウントに空の別アカウントを発行したりしない。

単一DOへのアクセス集中時の待ち時間、実データ量でのCPU・メモリ・D1無料枠、公開カタログの更新運用も確認が必要。元の公開デモの共通推薦順位という仕様を保持する実装であり、各利用者の評価から順位を独立して再計算する新機能を実装済みとは扱わない。

## 本番切替に必要な外部準備

1. 実稼働の記録DB・認証DB・pepper・公開カタログ・既公開の共通推薦・必要な画像の保護されたバックアップ。
2. 本番／検証D1とCloudflare管理操作への接続。現在の実行環境には管理用の秘密情報や接続済みIDが提供されていない。
3. 利用者単位の原子的な移行と、全表・全列・件数・checksumの読戻し照合。
4. 公開先での保存、復旧、再デプロイ、バックアップ復元、Render遮断の確認。

`local`持ち主のuser_id付きDB表には、運営が明示的に指定した新しい非local本人IDへ移す工具を追加した。行の所有値・複合主キー由来キー・checksumを再計算し、既存アカウントへ統合・上書きしない。復旧コードは別の0600ファイルへ出し、Webのowner権限を与えない。ただし私有設定JSON・共有表・素材・実際の購入由来データの全件取得と照合は未実施。利用者別の表を移しただけで全データ移行済みとはしない。
