## 今回できたこと

- 元HTML/CSS/JSと17画面のPython生成・一般操作を再利用。新しいデザインへの置換を行わない。視覚比較の完了とは区別する。
- 本人の全user_idテーブル・全列をD1へ保持し、変更行だけを原子的に保存する。競合時の上書きを防ぐ。作品評価と回別メモの元仕様を保つ。
- 通常利用者の同ID移行と、持ち主localから明示した新しい本人IDへの移行を用意。複合主キー・checksumを再計算し、既存利用者への合流・上書きを拒否する。
- 復旧コード、Cookie、旧認証の対応、端末追加、登録停止、本人の書き出し・削除を接続。復旧コードやメール本文などを操作ログに含めない。
- 秘密設定・実データ・生成bundleを公開対象から外し、uv.lockを公開対象に含める。新規checkout相当の合成入力ビルドを試験した。

新しいPython版は別Worker・別検証DBの設定で、`MIGRATION_READY=false`、登録停止、DB ID placeholderを保持する。現行本番の`ORIGINAL_UI_BRIDGE=true`は維持する。公開コードをそのまま本番完成版と扱わない。

## 完全移行に残るもの

1. **実ランタイム検証:** Python Workers/DO/実D1で起動し、全一般POSTと17画面を確認する。PC/スマホ34画面の見た目・操作を元版と比較する。ローカルはsocket制限でブラウザ・workerdを実行できず、現在のCI runtime/visualも従来JS bridge版の試験である。
2. **実全件の移行:** Renderの記録DB・認証DB・秘密pepper・私有設定JSON・共有表・承認済みカタログ/推薦・画像を保護された方法で取得する。全利用者と持ち主の購入由来記録を、件数・内容・関連付け・checksumで照合する。今は合成データでの工具試験のみ。
3. **継続運用:** バックアップを別DBへ復元、再デプロイ、Cookie期限と端末変更、無料枠使用量・集中時の待ち時間、素材とカタログ更新を実測する。100人の検証上限・30日セッションの本番方針を確定する。
4. **切替:** 検証済みDBへ最終差分を移し、公開先を切り替え、Renderを遮断しても動くことと切り戻しを確認する。その後にRender停止を判断する。

本人snapshotの再取り込みUIは元版にはない追加の復元受入条件で、今回未実装。利用者別のJSON/ZIP出力が成功しただけで復元成功とはしない。

## 運営と利用者が必要なこと

運営にはRenderバックアップへのアクセスとCloudflare/D1の管理接続が必要。現在の作業環境にはCloudflare管理用の秘密情報・接続IDと、実稼働データが提供されていない。秘密pepper、API token、復旧コード、実利用者DBを公開GitHubやチャットへ貼らない。

利用者はCloudflare・GitHub・Supabaseを契約する必要はない。一般公開前に登録停止を解除し、初回利用・Cookieと復旧コードによる継続利用・別端末追加・本人出力/削除の案内を検証する。現方式はメール/パスワード登録ではない。利用者ごとのGmail OAuthによる購入メール取込は今回未実装で、運営者の既存取込とは別作業。

有料プラン変更、Supabase契約、有料ドメイン追加は行っていない。無料対応構成であることと、実際の利用量が無料枠に収まることは別に確認する。
