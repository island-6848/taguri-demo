## 1. 一言で言うと

**ショートカットを 1 つ押すと、今週観るべき公演の一覧が開き、その場で 3 つのボタンと評価を押すと、次に押したときにそれが反映されている。** これが「たぐり」の全体である。企画書が主張する「見逃さない」を実現する部分（材料を集めて並べる部分）はすでに個別に動いていた。実装タスク #000007 で作ったのは、それを 1 本のコマンドにつなぐことと、画面から押した反応を次回の計算に戻す輪を閉じることの 2 つだけである。

**残り日数の都合で、完成の線は「一周」に絞ってある。** 写真からの公演特定、記録を見返す画面の作り替え、名前や題材での検索の強化は、一周が閉じたあとに回す（2026-08-24・起案者の判断）。

## 2. 全体の流れ

利用者が行うのは `python3 tools/taguri/run.py` を打つ（またはショートカットを押す）ことだけである。そこから先は、内部で次の順に進む。

```
① 購入確認メールの差分を取り込む（--mail 指定時のみ）
② 評価待ちの公演を洗い出す
③ 新しい候補を取得し、あらすじを抽出する（--fetch 指定時のみ・月1回・約5分）
④ お気に入り登録名で直接検索する
⑤ カレンダーを取り込む
⑥ 推薦を計算し、出した一覧を保存する（presented）
⑦ 差分のポスターを取り込む
⑧ 記録を見返す画面の材料を組み立てる
⑨ サーバを起動し、ブラウザで開く
```

**外部とのやり取りで失敗する段（①③④⑤⑦）では止めない。** 認証や相手のサーバ、API の枠といった外の都合で落ちる段であり、そこで止めると一覧そのものが開かず、その週は何も見ないことになってしまう。取れなかったことは画面に出すが、開くことを優先する。

**止めるのは⑥だけである。** 推薦の計算と一覧の生成が失敗したら、出すものが無いので、そこで打ち切る。したがって④・⑤（母集団を作る段）を飛ばして⑥へ進むことはできない ── 反応を書き戻す先そのものが、この段で決まるためである。

一覧が開いたあとは、画面はサーバに常駐しない。ブラウザで押した内容は都度 `data/review/ratings.db` に書き戻され、**画面を閉じるとプロセスは自分で落ちる**（詳細は 6 章）。

## 3. 画面とナビゲーション

**入口は 1 つで、画面は左のナビゲーションで移動する 1 つのシステムである。** 画面ごとに別々の HTML を書き出して開かせる形はとっていない。

左のナビゲーションは 8 つの行に分かれ、そのうち 3 つは開閉できる束（クリックすると子が開く。行き先ではない）である。「はじめる」は、まだ出せるもの（推薦・お気に入りの新着・観た記録）が無いあいだ、`/` を開くたびにその場で差し替わる入口で、ナビゲーションには出ない（詳細は次の節）。

| 束 | 子 | 道 | 何をする画面か |
|---|---|---|---|
| **おすすめ** | 今週のおすすめ | `/recommend` | 答え。順位付き 15 件と、追いかけない束 |
| | 開幕リマインド | `/recommend/reminder` | 答えていない候補・興味あり・お気に入りのうち初日が近いもの |
| | 興味あり | `/recommend/interest` | 「興味あり」を押した公演を追いかける |
| | お気に入り | `/recommend/favourites` | 登録した名前の新着 |
| （単独） | 公演カレンダー | `/calendar` | 券がある／興味あり／お気に入りの 3 つの束をまとめて見る暦 |
| （単独） | 購入済み公演 | `/tickets` | すでに券を買って、これから観に行く公演の一覧 |
| **観た公演の評価** | 評価一覧 | `/rate` | 過去に付けた ◎○△× の一覧 |
| | 未評価 | `/rate/unrated` | まだ評価していない、観た公演 |
| | 感想 | `/rate/notes` | 書いた感想 |
| （単独） | 公演情報の登録 | `/register` | 入力専用（読む画面とは分ける） |
| **記録を見返す** | 眺める | `/records` | 図で全体の形を見る |
| | たどる | `/records/trace` | 1 人の作り手を選んで、その糸を時間の上で読む |
| | 観劇史年表 | `/records/chronicle` | 記録を年の順に並べ、その年に何が始まったかを見る |
| | 日記帳 | `/records/works` | 1 公演ごとの記録 |
| （単独） | 探す | `/search` | 名前・題材・題名で過去を辿る |
| （単独） | 設定 | `/settings` | 決めごと（都道府県の既定）と、たまにしか押さない道具（書き出す・別の端末に記録を移す） |

**答えを出すのは「おすすめ」だけである。** ほかの画面はすべて、答えを作るための材料を見せているか、答えに対する反応を受け取っているかのどちらかであり、この線引きが画面の設計原則になっている。

### 各画面でできること

画面ごとに、実際に押せる・入力できる操作を挙げる。読むだけの画面（図・一覧）は、そう明記する。

**はじめる**（`/start`。「登録していないとき」ではなく、「まだ出せるものが無いとき」に開く。`/` を開くたびに毎回判定し直しており、名前を登録しただけではこの条件から外れない ── 候補を取り寄せて初めて「今週のおすすめ」側になる。この判定に関係なく `/start` へは直接いつでも行けるが、ナビゲーションには出ない）
- 見逃したくない名前を登録できる（劇団・俳優・演出家・作品・原作者・題材のどれでも）
- 登録した名前を外せる

**今週のおすすめ**（`/recommend`）
- 各公演に「すでに持っている／興味あり／興味なし」の 3 択を押せる。「興味あり」はその場で「なぜ気になったか」を、「興味なし」は「見送った理由」を書ける（どちらも任意）
- 都道府県で絞り込める
- 「効かせ方」（人物・題材などの重み）を調整できる
- 評価待ちの公演には ◎○△× を付けられる。押すとその場で感想欄が開く

**開幕リマインド**（`/recommend/reminder`）
- 「今週のおすすめ」と同じ 3 択・理由欄（対象は、初日が近い未回答・興味あり・お気に入り）

**興味あり**（`/recommend/interest`）
- 各公演に 3 択を押せる。「すでに持っている」を押すと観る予定に移る
- 書いた理由を読み返せる・書き直せる

**お気に入り**（`/recommend/favourites`）
- 名前を新規登録・解除できる
- 出さないと決めた語（除外ワード）を追加・解除できる
- 理由文から拾った「昇格候補」の名前をワンクリックで登録できる
- 3 択は無い（読むだけのお知らせという設計・2026-08-24 の決定）

**公演カレンダー**（`/calendar`）
- 束（券がある／興味あり／お気に入り）・都道府県で絞り込める
- 「行く日を入れる」で観る回を登録し、確定・取り消しができる

**購入済み公演**（`/tickets`）
- 「行く日を入れる」で観る回を登録・確定・取り消しできる（暦と共通の道具）
- 3 択は無い（すでに答えが決まっている束のため）。都道府県順（北から南）に並ぶ

**評価一覧**（`/rate`）
- ◎○△× の札で絞り込み表示を切り替えられる
- 各行で評価を付け直せる、感想を書ける・読み返せる

**未評価**（`/rate/unrated`）
- 各公演に ◎○△× を付けられる、感想を書ける

**感想**（`/rate/notes`）
- ◎ を付けた作品に感想文を書き足せる

**公演情報の登録**（`/register`）
- 観た公演を手動で登録できる（題名・日付・劇場・候補からの選択）
- 「観ればよかった」公演を登録できる（登録すると自動で演者・あらすじを調べる）
- 購入確認メールの取り込みを実行できる
- 似た記録が見つかったとき「まとめる／別の公演のままにする」を選べる

**眺める**（`/records`。もとの「比べる」を統合し、「相関図」として独立させていた
「一緒に出てくる人の網」も 2026-08-27 にここへ戻した）
- 図を読むだけ。図の点・行から日記帳の該当記録へ飛べる
- 「一緒に出てくる人の網」だけは、この図から分かる文章を LLM に作らせる押し口がある

**たどる**（`/records/trace`）
- 作り手の名前を選んで、その人の年表に切り替えられる。結び目から日記帳の該当記録へ飛べる

**観劇史年表**（`/records/chronicle`。2026-08-26・起案者の指示でもとの「眺める」の図の
1 枚から独立させた画面。中身は変えていない）
- 図を読むだけ。「年表の文を作り直す」で、その年に何が始まったかを語る文章を作り直せる

**日記帳**（`/records/works`）
- 各記録に ◎○△×・感想を付けられる
- 「公演詳細を直す」で題名・上演日・劇場を修正できる
- ポスター・出演者を手入力できる、外部サイトへの結び付けを直せる
- 記録を取り消せる（2 回押しで確定）・取り消した記録を復元できる
- 「行かなかった／やはり観た」を切り替えられる
- 購入確認メール本文の表示・非表示を切り替えられる

**探す**（`/search`）
- 語句（人名・団体・題材・題名）や月で絞り込んで検索できる
- 見つけた記録にその場で評価・感想を付けられる。これから観られる公演には「興味あり」を押せる

**設定**（`/settings`。決めごとと、たまにしか押さない道具を並べた画面。もとは「書き出す」だけが独立した画面だったが、2026-08-26・起案者の指示で設定に統合した）
- 都道府県を選んで、既定の絞り込みとして保存できる。次に「今週のおすすめ」を開いたとき、その都道府県で絞り込んだ状態になる。**すでに興味ありを押した公演・お気に入り・買った券には効かない**（一度決めたことを設定で見えなくしない、という原則）
- **書き出す**: 記録・評価・感想・お気に入りを、ほかの道具でも読める形（JSON）で 1 つのファイルに保存できる。ポスター・半券の写真は含まない
- **別の端末に記録を移す**: `data/review` フォルダの中身（記録・取得物・ポスター）を丸ごと 1 つの ZIP としてダウンロードできる。別の端末で続きから使うには、展開してその端末の `data/review` フォルダに置き換え、`run.py` を実行する。**LAN や外部サーバーは経由しない**（127.0.0.1 限定という守りを崩さないため）。運ぶ手段（クラウドストレージ・USB など）は本人に委ねる

### 束を「行き先と兼ねさせない」という決め方

3 つの束（おすすめ／観た公演の評価／記録を見返す）は、いずれも親の行を押すと開閉するだけで、画面そのものには飛ばない。**最初は親が 1 段目の画面を兼ねていたが、それだと「いま子のどれを見ているか」が左のナビゲーションの濃淡だけでは分からなかった**（起案者の指摘・2026-08-25）。子を必ず 3〜5 個の実在する画面にし、親を押し口専用にしたことで、3 つの束すべてが同じ形になっている。

## 4. データの置き場所

**書き戻しが要る「状態」は SQLite 1 本（`data/review/ratings.db`）に集め、外部から取ってくる「取得物」は JSONL のまま置く。** 取得物（候補・クレジット・あらすじ）は消えても取り直せるが、状態が 2 か所に分かれていると、画面からの書き込みと次回の読み出しが別の経路を通ることになり、反映漏れが起きる（過去にこの構造で反映漏れが実際に起きたことがある）。画面から書き戻すのは状態だけなので、取得物を DB へ移す作業は一周の完成に何も足さない。

### 状態（`data/review/ratings.db`）

| テーブル | 何を持つか |
|---|---|
| `works` | 公演ごとの評価（◎○△×）・感想・観劇回数 |
| `attendance` | 誰がその公演に行ったか |
| `splits` | 1 回の購入が複数の演目にまたがるときの、演目ごとの分け方（`rate_performances.py`） |
| `excluded` | 購入確認メールの候補から「舞台ではない」と外した演目の記録（`rate_performances.py`） |
| `fixes` | 人が直した公演詳細（題名・上演日・劇場・開演時刻。`tools/tickets/corrections.py`） |
| `merges` | 表記違いの同じ公演を、本人の判断で束ね直した記録 |
| `hand_credits` | 公演ページが存在しない公演のために、本人が直に入れた出演者・作り手・ポスター |
| `visit_note` | 観た回ごとのメモ。推薦の計算のどこからも読まない（起案者の指示・2026-08-26） |
| `presented` | 出した一覧のスナップショット。**上書きしない**（週ごとに残す） |
| `viewed` | 実際に画面に出した一覧の記録（計算しただけの一覧と区別するため） |
| `reaction` | 観る前の反応（興味あり／興味なし／すでに持っている・決め手・一言） |
| `ticket` | 券。観る回ごと（同じ公演の昼夜・初日と楽日は別行） |
| `missed` | 「観ればよかった」の申告（`serve.py` 側で追加） |
| `rank_weight` | 画面から調整した推薦の重み |
| `app_setting` | 都道府県の既定など、鍵と値だけを持つ設定の保存先（`app.py`。項目が増えても列は増やさない） |

### 取得物（`data/review/` 配下、JSONL）

候補・あらすじ（機械抽出／LLM 抽出の 2 種）・お気に入り・カレンダーの、あわせて 5 本。すべて取り直しがきく。

## 5. 状態が変わる規則

システムの中核は「提示 → 反応 → 次回の計算に反映」の輪である。この輪の規則をここにまとめる。

- **観る前の反応は 3 択だけ**（すでにチケットを持っている／興味あり／興味なし）。これを押すと `reaction` に `source='screen'` の行が入る。
- **「興味なし」を押した公演は、次週は「その他」の束へ移る。** 「すでに持っている」は推薦の枠の外へ、「興味あり」は追跡枠へ、それぞれ移る。
- **観たあとの評価（◎○△×）は評価一覧の画面で入力し、`works.verdict` に入る。** 観る前の反応とは別の表・別のタイミングで書く（観る前と観たあとを混ぜない）。
- **答えなかった公演は、畳まずに翌週もそのまま出す**（2026-08-24・起案者の判断）。一度出したら畳んで初日の 1 週前に上げ直す案は採らなかった ── 畳むと、答えなかった公演が本人の意思と関係なく視界から消えてしまうためである。この結果、枠が詰まる（新しい公演が出てこなくなる）問題は残るが、これは限界として書き、対処は母集団を増やす側（取得の範囲を広げる）で行う。
- **券（`ticket`）は本人が入れた行は最初から確定済み、購入確認メールから機械が起こした行は未確定で始まり、画面の「確定」操作で確定に変わる。** 探すのは機械、確定するのは人、という役割分担を券の記録でも保っている。

## 6. 実行環境としての制約（守りの設計）

一時プロセスとしてローカルにサーバを立てる構成をとっている。**当初は「静的 HTML を `file://` で開く」構成だったが、これは撤回した。** `file://` で開いた HTML は SQLite に 1 文字も書き戻せず、企画の中核（反応を次週の推薦に戻す輪）が成立しないためである。「サーバを立てない」という機密性の方針は「公開されたサーバとアカウントを持たない」ことを指しており、端末内で完結する一時プロセスまでは禁じていない。

この一時プロセスが守る 4 点:

| 何をするか | なぜ |
|---|---|
| **待ち受けを `127.0.0.1` に固定する** | `0.0.0.0` で待つと、同じ LAN の他の端末から観劇記録を読めてしまう |
| **起動ごとに乱数のトークンを作り、これを持たない要求は受け付けない** | ローカルでも、同じ端末の別プロセス（他のタブで開いた外部サイトを含む）は `127.0.0.1` に到達できるため |
| **書き込める操作を指定する ── 任意の操作を許さず、押せる操作を最初から決められた種類だけに絞る** | 任意のパスも任意の SQL も受けない。操作を数え上げられることが、書き込み口を持つための条件である |
| **常駐はさせないが、画面を閉じただけでは自動終了しない** | 画面の「終わる」ボタン（`/api/close`）か `Ctrl-C` で終了する。ブラウザが一度も開かないまま 30 分たった場合だけは、開き忘れとみなして自動で落ちる |

**画面を閉じたことを自動で判定する仕組みは、2026-08-27 に撤回した。** 当初はページを離れる合図（`pagehide`）で終了させていたが、この合図は画面内の移動（ナビゲーションを押す）でも発火してしまい、移動するたびにシステムが落ちる不具合になっていた。**そこで 15 秒ごとの心拍（合図）が 90 秒途切れたら落ちる方式に直した**が、これも「記録を見返す」のような画面を長時間開いたままにする使い方と噛み合わなかった ── タブを裏に回すとブラウザが定期送信を間引くことがあり、まだ見ているのに落ちることがあった（起案者の指摘）。**「長時間開いたままにできること」を優先し、自動終了そのものをやめた。** 閉じるのは、押すと終了する画面のボタンと `Ctrl-C` に一本化してある。

## 7. 意匠（画面デザイン）の決まり

案A「幕と紙」を採用している。詳細な色・形の規約は `tools/taguri/test_design.py` が機械的に検査しており、特に崩れやすい 2 点は次のとおりである。

- **押せるものだけを藍色にする。** 藍色を線や装飾に使うと、押せないものが押せるように見えてしまう。
- **判子と封蝋は同じ版（CSS のフィルタ参照）を共有している。** 参照先が無いと、薄く出るのではなく要素ごと描かれずに消える。

比喩は形と動きだけで出し、画面の文字には「たぐる」「糸」のような作り手側の呼び名を書かない。文字には押した結果を書く（既存の画面文言の規約と同じ）。

## 8. 完成の線（完了条件）

一周だけを完成とする。次の 7 点をもって完了とする。
