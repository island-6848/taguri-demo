## 1. 判定の基準

### 1.1 品質を何で見るか

| 観点 | 良いとは | 合格のライン | 主なケース |
|---|---|---|---|
| 正しさ | 要件どおりの結果が、画面と D1 の行の両方に出る | 必須のケースがすべて OK | FN 全部 |
| 分離 | 他人の記録が、どの画面・書き出し・API にも出ず、変えられない | 漏れ・書き換えが 0 件 | SC-01〜03・FN-10 |
| 保持 | 再配備・migration・配送・切り替え・戻しのあとも記録が同じ | 件数と中身の食い違いが 0 件 | OM-02・MG-03・AV-03〜04 |
| 止まらなさ・戻しやすさ | 止まれば 1 時間以内に気付き、4 時間以内に戻せる | 通知が届く。予行で測った戻す時間が 4 時間以内 | AV 全部 |
| 速さ・軽さ | 1 回の CPU が無料枠の 10 ミリ秒に収まり、D1 の読み書きが少ない | 計画書 PF の基準 | PF 全部 |
| 安全 | 入れた文字が動かず、秘密が出ず、濫用で費用が増えない | 実行・漏れ・上限越えが 0 件 | SC 全部・PF-05 |
| 使いやすさ | 初めての人が説明なしで進め、主な端末で操作が通る | 計画書 EN・ベータの基準 | EN-01〜04・BT |
| 無料枠 | 試験を通して使う量が上限より十分少ない | どの項目も 8 割未満。請求 0 円 | 全ケースの前後の確かめ |

### 1.2 1 件ごとの判定

| 判定 | 意味 |
|---|---|
| **OK** | 期待結果をすべて満たし、証拠が残っている |
| **NG** | 期待結果のどれかを満たさない。不具合の issue を作る |
| **保留** | 前提がそろわず流せない（実機が無い・上限で止められた・別の作業待ち）。理由と、いつ流すかを書く |
| **対象外** | この版では流さないと決めた。理由を書く（起案者の了承が要る） |

**証拠が無ければ OK にしない。** 証拠は、ケースの「証拠」の列のもの（画面の写し・D1 の行・コマンドの出力・実行の Summary・ログ）を、手順書 0.4 の記録に貼るか、置き場所を書く。
**ローカルの OK は、本番で確かめるケースの OK に数えない**（環境が「P」のケースは本番で流して初めて OK）。

### 1.3 不具合の重さ

| 重さ | 例 | 扱い |
|---|---|---|
| 致命 | 記録が消える・他人の記録が見える／変えられる・無料枠を越えて請求される・秘密が漏れる | その場で試験を止め、起案者に知らせる。直すまで次の段に進まない |
| 重い | 主な操作（登録・ログイン・記録・評価・削除）が通らない・見張りが鳴らない・戻せない | 直してから判定 |
| 軽い | 表示の崩れ・文言の誤り・遅いが基準内 | 判定までに直すか、残す理由を記録する |

### 1.4 段と全体の合格ライン

| 区切り | 合格のライン |
|---|---|
| 1 つの段（手順書の P-xx） | その段の必須のケースがすべて OK か、起案者が了承した保留。新しい致命・重いが 0 件 |
| 回帰（直したあと） | 直したケースと、下の 1.5 で決めた周りのケースがすべて OK |
| 全体（一般公開の判定） | 1. 必須のケースが 100% OK<br>2. 任意のケースの 8 割以上が OK で、NG・保留はすべて理由が書いてある<br>3. 致命・重いの未解決が 0 件。最後の回帰で新しい重い以上が 0 件<br>4. ベータを通して記録の消失・混在が 0 件<br>5. 試験の期間を通して、無料枠のどの項目も 8 割未満。請求 0 円<br>6. S11（取得元の条件）・S25（説明と実装の一致）の確認が済んでいる |

### 1.5 やり直す範囲（回帰）

| 直したところ | やり直すケース |
|---|---|
| 画面 1 つ（`src/screens/*`） | そのケースと FN-12（一致・見た目）・SC-04（入れた文字） |
| ログイン・セッション（`passkey.js`・`firebase-auth.js`・`session-policy.js`） | FN-01・FN-02・FN-10・SC-01〜02 |
| 保存・migration（`migrations/*`） | OM-02・OM-03・SC-03・FN-09 |
| 無料枠・回数制限（`free-tier.js`・`rate-limit.js`） | AV-05・PF-05・SC-05・OM-04 |
| 推薦（`recommend.js`・索引） | FN-05・PF-01・PF-02 |
| 何でも（毎回） | 自動試験一式（P-02）と通し検証（P-03） |

## 2. 担当

この作業環境（Claude のセッション）からは、本番の Worker・Cloudflare の口座・非公開の taguri-crawler に届かない（本番への通信はプロキシが 403 で止める）。
だから **本番・Cloudflare・実機で手を動かすのは起案者**、Claude はその手順・確かめる表・記録の下書きを用意し、結果を読んで判定の案を書く。

| 記号 | 誰 | 受け持つこと |
|---|---|---|
| **CL** | Claude（セッション） | ローカル・CI のケースを流す。試験を書き足す。手順と記録の下書き。不具合を直す。結果をまとめ、判定の案を出す |
| **OW** | 起案者 | 本番の操作、Cloudflare・GitHub・Firebase の管理画面、`wrangler` の `--remote` の操作、taguri-crawler の手動実行、実機。判定 |
| **BT** | ベータ参加者 | 招待制ベータでの利用と、BT のケース |

ケースの表の「担当」は **実施する人／準備する人**（例: `OW／CL` は、Claude が手順を用意し起案者が流す）。
