# taguri-bot：公演情報の取得について

このページは、User-Agent が `taguri-bot/1.0 (+このページの URL)` の取得プログラムについての説明です。サイトの運営者の方へ向けて書いています。

## 何のために取得しているか

「たぐり」は、観た演劇の記録から、これから観られる公演をおすすめする個人開発のアプリです（[リポジトリ](https://github.com/island-6848/taguri-demo)）。公演の題名・日程・劇場・出演者・あらすじと、ポスター画像を、公演を見逃さないための一覧づくりに使います。

取得した情報を第三者へ再配布することはありません。データは非公開の保存場所に置き、アプリの画面にだけ使います。

## 取得の作法

すべての取得は、共通の入口（[`tools/lib/polite_http.py`](../tools/lib/polite_http.py)）を通ります。

- **名乗る：** User-Agent に、このボットの名前とこのページの URL を入れます。ブラウザを装いません。
- **robots.txt に従う：** ホストごとに最初に読み、禁止されたパスへは行きません。`Crawl-delay` があれば、その秒数に従います（60 秒まで）。robots.txt を読めなかったとき（5xx や通信失敗）は、その回はそのホストへ行きません。
- **間隔を空ける：** 同じホストへは、1.1 秒に 1 回までです。
- **待ってと言われたら待つ：** 429 と 503 には、`Retry-After` の秒数だけ待ってから 1 回だけ取り直します（120 秒まで）。
- **断られ続けたら引く：** 同じホストから 403・429・503 が 2 回続いたら、その回はもうそのホストへ行きません。
- **取り直しを減らす：** 一度取ったページは手元に控え、同じページを何度も取りに行きません。到達できなかった先は 30 日間控え、その間は再挑戦しません。
- **時間帯：** 定期の取得は日本時間の早朝（4 時台）に、開始時刻を少しずつずらして行います。頻度は、一覧の取り直しが 1 日 1 回、出演者などの詳しい取得が週 1 回です。

## 量の上限

取得の量は、相手のサーバーへの配慮（1.1 秒に 1 枚）に加えて、**無料枠の中に収まる分だけ**にしている。動かしている GitHub Actions の
無料の分（月 2,000 分）を越えないよう、毎日のジョブが読む枚数を決める（`docs/free-tier-budget.md`）。

## 止めてほしいとき

次のどちらでも止まります。

1. robots.txt に、次のように書いてください。次の実行から、指定したパスへは行きません。

   ```
   User-agent: taguri-bot
   Disallow: /
   ```

2. [リポジトリの Issues](https://github.com/island-6848/taguri-demo/issues) でご連絡ください。取得先から外します。
