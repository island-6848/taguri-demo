# たぐり ── 演劇の推薦・観劇記録システム

観た演劇の記録・評価・お気に入りをもとに、次に観るべき公演を提示するWebアプリです。個人開発。

**デモ**: https://taguri-demo.onrender.com/

## これは何か

演劇は「一度きり」「情報が探しにくい」というジャンルの特性上、既存の推薦サービスがあまり機能しません。このシステムは、

- 観た記録・評価（◎○△×）・感想・お気に入りを蓄積し、
- 公開されている公演情報（CoRich等）と突き合わせて、
- 次に観るべき公演を毎週提示し、
- 提示への反応（興味あり／興味なし等）を次の推薦に反映する

という「観る→記録する→次が良くなる」循環を作ることを目的にしています。

## 設計上のこだわり

- **推薦のランキングにLLMを使わない。** あらすじの要素抽出のような境界が決まった変換にはLLM（Gemini API）を使うが、順位づけ自体は記録から数えた統計処理で行う。理由と実測は`docs/000007-taguri-design.md`を参照。
- **アカウント登録なしの認証。** メールアドレス・パスワードを持たず、初回アクセス時に発行される復旧コード（128bit）とセッションCookieの二層構造で利用者を識別する。パスワードDBの漏洩・使い回しによる不正ログインといった攻撃面を構造的に持たない設計。実装は`tools/taguri/auth.py`。
- **外部送信を絞る。** 画面からは外部サイトを直接叩かない。取得は専用のバッチ処理のみが行い、1リクエスト/秒を守る。詳細は`docs/000007-taguri-security-rules.md`。
- **標準ライブラリのみで動く。** pipでの追加インストールを前提にせず、`urllib`・`sqlite3`・`http.server`で完結させている（環境が変わっても壊れないため）。

## 技術構成

- Python標準ライブラリのみ（Webフレームワーク不使用、`http.server`を直接使用）
- SQLite（永続化）
- Gemini API（あらすじ・要素抽出のみ、順位づけには使わない）
- 公演情報の取得元: CoRich・ステイジーズカレンダー

## ローカルで動かす

```bash
python3 tools/taguri/run.py --no-open   # 動作確認用（画面は開かない）
```

## 補足

このリポジトリは公開用に、実データ・検証記録を除いたコードとドキュメントのみで構成しています。デモ用の体験データ（`data/review/`）は架空の評価・お気に入りを含みますが、公演情報自体は実在するものです。
